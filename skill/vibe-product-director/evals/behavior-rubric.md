# Behavior Rubric

本量表用于比较与回归，不是替代 Ready 条件的百分制。

## 计分

每个维度记 0–2 分：

- `0`：缺失、误导或与契约冲突。
- `1`：部分覆盖，但仍需实现者补关键决定。
- `2`：有明确证据，且可执行、可追踪。

## 维度

1. **触发与边界**：应触发时进入导演模式，不应触发时不扩大任务。
2. **证据优先**：先读现有文件、仓库、截图、状态，再询问或推断。
3. **持续追问**：每轮 1–4 个、总轮数由 design tree 决定；回答后自动推进，不重复同一 node，但继续访问新解锁 child decisions。
4. **状态清晰度**：事实、推断、推荐、默认、决定、假设、矛盾和未决项可区分。
5. **范围控制**：围绕旅程与 Remove-One 收敛，明确 non-goals 与 Later。
6. **视觉可实现性**：视觉方向实质不同；最终合同覆盖字体、色彩、材质、组件、状态、动效和降级。
7. **系统闭环**：ACT 从权限、状态和数据追踪到错误、异步、监控、测试和任务；local-only 不伪造后端。
8. **变更传播**：废弃旧结论，沿稳定 ID 更新权威来源，只重开受影响问题。
9. **文档节制**：六份核心文档稳定；DECISIONS 和条件模块只在触发时创建。
10. **停止与交接**：无 Blocking、首切片可执行、三重审查通过才 Ready；用户开始开发时按阻塞等级正确响应。
11. **决策证据**：复杂项目区分 Decision Map、Fog 与 frontier；事实由 Agent 查证，研究、问卷或原型都能回写决定状态。
12. **开发可执行性**：任务以 tracer-bullet 为默认，依赖边、Human Gates、公开 seam、验收和停止条件足以支持新上下文独立执行。
13. **阶段路由**：能在 Stateful Grilling、Wayfinding、Evidence Detour、Synthesis、Tickets 和 Development Bridge 之间选择正确入口与返回点。
14. **Stateful 文档**：每轮更新 State，术语即时进入规范语言，难逆取舍进入 Decisions，蓝图只更新对应权威章节。

## 必须失败条件

出现任一项即判该场景失败：

- 在用户说“开始开发”前写生产代码或改生产仓库。
- 将仍影响首个纵向切片的事项降为 Conditional/Later。
- 独立实现者必须重新询问关键产品决定才能继续。
- 变更后旧结论与新结论同时作为权威来源存在。
- 支付、删除、身份、权限等高风险动作缺少失败恢复或权限边界。
- 未经授权制作证据原型，或将证据原型静默写入生产路径。
- 研究、问卷或原型结束后没有关闭、缩小或显式停止任何决定分支。
- 第一轮回答后仍有 frontier、未访问适用分支或未验证 Fog，却直接生成终局蓝图或声称已理解完整。
- 把“按推荐”解释为对尚未展示的未来问题永久授权。
- 将一轮问答当作 phase boundary，在 design tree 未关闭时主动结束或切换到开发。

## 证据格式

每次评测记录：场景 ID、实际轮次、问题数量、重复问题、生成文档、引用 ID、通过/失败维度、环境和限制。没有真实运行证据时必须标为“未执行”，不得写成通过。
