# Adaptive Modes and Change Control

仅在非默认模式、暂停恢复、旧版蓝图迁移或已批准决定发生变化时读取。

## 1. 三个组合维度

不要把八种行为做成互斥菜单。推断默认组合，只在组合会实质改变投入、风险或输出时告诉用户。

### Context

- **Greenfield**：没有可依赖的现有实现或蓝图。从用户、问题、结果和平台建立项目锚点。
- **Existing Product**：存在代码、设计、运行产品或真实数据。先读取证据并创建 `CURRENT_PRODUCT_AUDIT.md`；问题只针对保留/改变/删除及代码无法回答的业务取舍。
- **Resume**：存在 `00_BLUEPRINT_INDEX.md`、`PROJECT_STATE.md`，或旧版 `00_INDEX.md`。先恢复状态、决定、风险、frontier 和上次最小行动。
- **Blueprint Revision**：用户改变已批准蓝图。只重开受影响的分支并传播决定影响。

### Depth

- **Express**：用户要求快速 MVP、连续授权默认或时间极紧。保留核心价值、体验契约、关键业务动作追踪和首个纵向切片；研究和低风险选项用默认。兼容用户说 Fast Track。
- **Standard**：默认。覆盖足以让首个纵向切片独立开发的所有决策。
- **Deep**：支付/资金、敏感数据、合规、多人/多组织权限、市场撮合、UGC、关键迁移、实时协作、高成本第三方或多平台发布等高风险项目。增加专门条件模块和更强证据。

### Focus

- **Visual-First**：只有在核心用户、核心任务、产品结果和平台约束基本清楚时使用。可以先探索视觉与主交互，但不能跳过功能和系统闭环。

## 2. Existing Product 审计

至少检查与当前改版相关的：

- 路由、页面、入口、核心组件和设计 tokens。
- 现有用户旅程、角色、权限和运营后台。
- 数据获取、接口层、认证、实体/迁移、文件和第三方集成。
- 测试、部署、环境变量示例、日志和监控。
- 必须保留的品牌、内容、数据、兼容行为和技术约束。

审计必须形成最小回归基线：每项必须保留的行为都指向可观察证据和对应自动化或人工回归测试。没有证据的“应该没变”不能作为护栏。

每项结论给出真实证据路径或截图来源。不要根据文件名猜实现，也不要重新询问已经能从代码确认的事实。

## 3. Resume 与旧版迁移

恢复顺序：

1. 读取新 `00_BLUEPRINT_INDEX.md`；若不存在，读取旧 `00_INDEX.md`。
2. 读取 `PROJECT_STATE.md` 与 `DECISIONS.md`（若存在）。
3. 找出 Approved、In Review、Blocking、Conditional 和最近变更。
4. 检查当前代码/文件是否已改变蓝图事实。
5. 从已有 frontier 或最早的真实阻塞继续。

发现 v1 的 18 份编号文档时：

- 把它们作为迁移证据，不把旧文件名继续设为 v2 权威来源。
- 在新 Index 列出旧资料范围、迁移状态和新的权威文档。
- 只将仍有效结论转入 v2；冲突内容进入 Conflict，不静默选择。
- 需要数据、架构或用户流程迁移时创建 `MIGRATION_PLAN.md`。

## 4. 自然控制表达

| 用户表达 | 行为 |
|---|---|
| 按你的推荐 / 你决定 | 接受当前推荐为 Authorized Default，记录理由与重开条件 |
| 快速一点 | 切换或加强 Express；只问 Blocking 或无法安全默认的高影响问题 |
| 先跳过 | 归类为 Conditional 或 Later；若其实 Blocking，说明阻塞并给最小替代 |
| 给我三个方向 | 在依赖满足后发散三个实质不同方向 |
| 融合 1 和 3 | 建立一个新决定，明确哪些维度来自各方向，避免模糊拼接 |
| 不要这个功能 | 移入 Reject，记录被删除的价值、连带影响和是否释放依赖 |
| 回到上一个决定 | 打开目标决定并运行影响传播 |
| 重新考虑视觉 | 只重开受影响的视觉、页面、性能、验收和任务内容 |
| 暂停 | 更新状态、最近变更和下一步最小行动后停止 |
| 继续上次项目 | 执行 Resume，不重复已闭合问题 |
| 开始开发 | 运行 Ready 检查；可交接则冻结，否则只处理 Blocking |

## 5. 决定传播算法

每个高影响决定至少记录：`ID / status / statement / source / depends_on / affects / rationale / reversibility / revisit_trigger`。

决定变化时：

1. 原决定标记 `Superseded by DEC-*`，保留历史理由。
2. 使用显式 `affects`、`depends_on`、稳定 ID 引用和文档链接扫描下游。
3. 受影响章节标记 `In Review`；过时内容写明替代来源或删除。
4. 先更新唯一权威来源，再更新 Index、State、追踪、测试和 tickets。
5. 重新检查依赖该决定的风险和 Conditional 默认。
6. 给用户一段影响摘要：改变了什么、受影响什么、哪些已自动更新、哪些必须重新决定。

## 6. 抗循环

- 无新证据不重开 Approved 决定。
- 一个决定最多一次必要深挖；后续追问必须由新矛盾或高影响风险触发。
- 每次研究先写清要解决的决定；结果已不能改变决定时停止。
- 不为 Later 项阻塞 Ready。
- 不重复生成同一信息；状态只保留一行摘要并链接权威内容。
- 每轮结束只展示用户当前需要的：已定、采用默认、风险/矛盾、下一 frontier。
