# Visual Experience System

进入视觉探索、页面体验设计、设计系统或动效契约时读取。

## 1. 审美翻译

禁止把“高级、炫酷、科技、年轻、文化感、沉浸、简约、大气、有质感”等词直接当作规格。翻译到：

- 构图、网格、留白、密度、视觉重心、对称关系和页面叙事。
- 字体性格、Display/Heading/Body/UI/Data 角色、中英混排、字号比例、字重、行高和字距。
- 色彩温度、明度、饱和度、对比、品牌/强调/表面/文本/状态/focus 角色。
- 图像、摄影、插画、图标、几何、纹理、材质、光线、深度、边界、阴影和模糊。
- 组件形态、状态反馈、动效强度、节奏、触摸/键盘行为、性能和可访问性。

视觉因果链：

```text
希望用户产生的感受或行为 → 信息层级 → 构图与排版
→ 字体与色彩 → 材质与图像 → 动效与反馈 → 性能/可访问性
```

## 2. 视觉方向

产品目标足够清楚且方向未批准时，通常提供三条覆盖稳健、辨识度和探索性的方向，但不要机械命名。每条方向至少在多个维度本质不同：

- 核心概念与用户感受。
- Hero/关键屏构图、信息层级和主交互载体。
- 字体、色彩、背景/图像、组件和动效语言。
- 响应式/移动替代、可访问性、性能、开发与内容成本。
- 适用场景、失败风险、明确禁止项。

有图像生成或设计工具时，在目标清楚后生成独立关键屏或情绪板；用户需要可编辑设计稿且 Figma 可用时再转成 frames、variables、components 和 variants。没有工具时使用文字情绪板、页面骨架、token 示例、Hero 构图和动效时间线。

已有批准设计系统时不强制三案；审计其是否支持新目标，并只探索真正受影响的部分。

## 3. 反 AI 模板审查

以下元素不是禁止，但必须说明目的、位置、成本、性能和降级：紫蓝渐变、Bento、卡片套卡片、玻璃拟态、发光按钮、粒子、3D、视频背景、所有内容滚动进入、持续漂浮、过量圆角/阴影。

删除或限制无法回答以下问题的效果：

```text
为什么使用？服务什么内容或行为？在哪个区域？
移动端如何替代？reduced-motion 如何降级？低性能设备如何降级？
```

优先用排版、间距、对齐和层级解决问题，再考虑边界/表面，最后才使用持续动画、视频、粒子或 3D。

## 4. 最终体验契约

`EXPERIENCE_BLUEPRINT.md` 的选定方向至少明确：

- 品牌性格与反性格、内容语气和关键视觉原则。
- 页面/屏幕地图、导航、入口、核心与替代流程。
- 各关键屏的目的、信息层级、主要/辅助动作和内容状态。
- 容器、网格、断点、间距、信息密度和响应式重组。
- 字体授权/fallback、中英混排及 typography tokens。
- 色彩、背景、图像、图标、材质、圆角、边框、阴影、模糊和层级 tokens。
- 组件、表单、focus/hover/active/disabled/selected，以及空、加载、失败、权限状态。
- Hero、页面转场、区块、组件、加载、拖拽和上传的动效规则。
- 触屏、键盘、reduced-motion、低端设备和性能预算。
- 可观察的视觉与交互验收标准。

## 5. 动效行为规格

每个重要动效记录：

```text
Purpose | Trigger | Target | From/To state | Visual properties
Timing or spring character | Interruption behavior
Touch alternative | Keyboard behavior | Reduced-motion fallback
Low-performance fallback | Acceptance criteria
```

动效应解释层级、因果、进度或状态。禁止只写“丝滑”“高级”或让所有元素持续运动。

## 6. 体验 Red Team

- 视觉是否压过主任务、阅读、可信度或转化？
- 首屏是否只有一个明确主信息和主动作？
- 高频工具是否被营销式动效拖慢？
- 桌面 hover 是否有触屏和键盘替代？
- 动效能否打断、撤销或在异步失败时回滚？
- 中文、英文、数字、长文和真实数据是否都可读？
- 低端设备、弱网和 reduced-motion 是否仍能完成任务？
